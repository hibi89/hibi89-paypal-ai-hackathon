# PayPal AI Hackathon — 확정 실행계획 v4.0 (단일 활성 작업자)

> 운영 변경 사용자 결정: **2026-10-24 KST**. 이 문서는 기존 v3의 **PayPal 담당자 3명 병렬 개발**을 명시적으로 대체한다. 예산 및 제출 목표는 유지. 아직 기능 실행·API 실증·배포·Devpost 제출은 없음.
>
> **전역 리소스 정책:** 3개 해커톤(KIC·PayPal·UGREEN)을 병행할 수 있으나, **각 해커톤당 활성 기능 개발자 1명만** 허용. **PayPal 내부에서는 담당자 3명을 동시에 가동하지 않고 차례로 한 명씩** 작업한다. 기존 3개 기능 브랜치는 유지하며, 현재 어떤 기능 작업자도 개발 착수가 검증되지 않았다. **실제 개발 작업자 채팅은 하나**를 재사용하며, 총괄이 lead/paypal의 현재 지시서로 브랜치를 바꾼다. 채팅/원격 브랜치 간 자동 통신은 없다.

## 1. 확정 전략과 성공 기준

- **제출물 1개:** 프리랜서용 AI 견적 → 사람 승인 → PayPal Sandbox 결제 → 납품 상태 → 구독/청구 예외를 다루는 통합 AI Agent.
- 기능 책임 3개는 **유지**: `feature/quote-payment`, `feature/delivery`, `feature/subscriptions`. 인력이 동시에 셋 투입되는 것을 의미하지 않는다.
- **추가 현금 지출 상한 0원**. 공개 GitHub·무료 Workers/D1·가용 무료 Gemini/Workers AI·PayPal Sandbox·무료 영상 도구 우선. 계정 접근/무료 정책/실 API 호출은 아직 미검증. 유료/API 계정 업그레이드·카드 등록·실금전 거래 불가(별도 사용자 승인 전).
- **PayPal만을 기준으로 일정을 설계**하고 다른 해커톤 일정이 PayPal 개발 단계를 자동 수정하지 않게 한다. 전체 차원에서 3개가 동시에 진행될 수 있다는 사용자 리소스 원칙은 준수.
- 우선 검증 순서는 결제 핵심 POC → 납품 → 구독 → 통합 품질. 단계/기능을 줄이려면 사용자의 별도 범위 변경 승인이 필요하다.
- 공식 제출: **2026-11-13 (금) 05:00 KST**. 내부 조기 제출 목표: **2026-11-11 (수)**. 이후 12/16 01:00 KST 심사 종료까지 무료 실행·재현 접근 유지.

## 2. 활성 작업자 슬롯 규칙 (가장 중요)

| 슬롯 | 할당 | 운영 상태 |
|---|---|---|
| PayPal 활성 슬롯 #1 | 견적·결제 / 납품 / 구독 중 **정확히 한 담당자** | 최초 예정: `feature/quote-payment` · **채팅 배정/실착수 미확인** |
| PayPal 대기 #1 | 그때 활성 아닌 첫 번째 담당자 | 개발 지시·수정·API 호출 없음 |
| PayPal 대기 #2 | 그때 활성 아닌 두 번째 담당자 | 개발 지시·수정·API 호출 없음 |
| PayPal 총괄 | `lead/paypal` 설계·검수·일정·보고 및 통합 판단 | 활성 담당자 슬롯을 다중 실행으로 우회하지 않음 |

- **사용자 추가 결정:** 3명의 역할별 채팅 대신 **작업자 채팅 1개**에서 [현재 지시서](dispatch/ACTIVE_TASK.md)를 조회하고 지시된 브랜치로 이동. 총괄은 [라우팅 프로토콜](dispatch/PROTOCOL.md)로 순서/검수를 관리. 
- 기존 브랜치·인수인계·요구사항 삭제하지 않음. **담당 AI 3명이 존재한다는 조직 구조**와 **동시에 1명만 작업한다는 자원 규칙**은 서로 모순되지 않는다.
- '다음 담당자 시작'에는 **이전 담당자 작업 중지 → 커밋/테스트 로그/STATUS/HANDOFF/`TO_PAYPAL_LEAD.md` 보고 → 총괄 원격 SHA 검증/인수 판정 → 다음 담당자 지시** 순서를 강제한다.
- 한 명이 보류·장애 상태라면 그 담당자를 **중지/대기**로 표시한 뒤 다른 기능을 시작할 수 있지만, 두 담당자에게 동시에 `ㄱ` 지시하거나 백그라운드 실행시키지 않는다.
- PayPal 총괄은 신규 작업 지시 전에 세 기능 브랜치의 최신 메시지함과 HEAD를 확인한다. 다른 해커톤 총괄을 직접 지휘하거나 그 브랜치를 수정하지 않는다.

## 4. 0원 아키텍처 및 안전 규칙

- 비용 상세·서비스 한도·Fail Closed 정책: [0원 스택과 과금 방지](ZERO_COST_STACK_AND_GUARDRAILS.md).
- 기본 후보: React/Vite UI + Cloudflare Workers Free 서버·정적 호스팅 + D1 Free DB + **현재 계정에서 무료 제공이 확인된** AI 모델 + PayPal Developer Sandbox. 설정/접근/국가 제한 검증 후 실제 채택. 외부 공개 테스트 데이터는 전부 가상.
- **실결제/Live API 금지**, 서버 측 금액 검증·human approval·요청 멱등·Webhook 서명 검증·중복 이벤트 방어. 브라우저 새로고침이나 페이지 조회로 주문/캡처 재실행 금지.
- 무료 한도 소진 시 호출 중단/오류 상태 고지, 초과 비용 발생 가능 서비스 무단 업그레이드 금지.
- 모든 증거는 PLAN/PASS/FAIL/BLOCKED/NOT TESTED 구분. `GitHub 문서 반영`은 실행 완료가 아니다.

## 5. 역할 인수 절차 및 최종 제출

- 총괄이 최초 `quote-payment` 활성 지정 후 담당자가 자기 브랜치에만 개발, 결과를 `STATUS.md`·`HANDOFF.md`·`docs/roles/quote-payment/TO_PAYPAL_LEAD.md`에 남긴다. 실제 채팅 배정 전이라면 '예정'이다.
- **다음 담당자 배정** 전에 이전 담당자의 중단·커밋 SHA/테스트 결과·총괄 인수확인을 기록한다. 모든 후속 단계 동일.
- 총괄 보고: `docs/roles/lead/MESSAGE_REVIEW.md`, `STATUS.md`, `HANDOFF.md`, `docs/roles/lead/TO_HACKATHON_LEAD.md`. 상위 총괄에 사용자 신규 규칙이 자동 전달되는 것은 아니므로 GitHub 보고를 통해 알린다.
- 제출 요건: 실제 PayPal + AI 동작, 심사 가능한 공개 저장소·상위 LICENSE·재현 안내/접근, 영문 설명·3분 미만 공개 YouTube 영상·Devpost 접수. 11/11 내부 목표, 11/13 05:00 공식 마감.
