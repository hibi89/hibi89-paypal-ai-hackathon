# PayPal 제출 이후 공식 Stage Two 심사 대응표 — 2026-10-24 기준 조건부

> 공식 규정: https://paypalaihackathon.devpost.com/rules / 공식 일정 https://paypalaihackathon.devpost.com/details/dates (2026-10-24 조회).
>
> **용어 정정:** PayPal은 KIC/UGREEN과 달리 *별도 본선 진출 팀 선발 후 제품 재개발·발표하는 단계가 공식 규정에 없다*. `Stage One`은 적합성 pass/fail, `Stage Two`는 해당 출품물 점수 평가. **Stage Two 통과만으로 공식 '본선 진출' 실적으로 표현하지 않는다.** 제출된 작품을 심사하므로 새 개발 일정이 아니다.

- **제출 마감 이후 Submission 원문·영상·제출 자료 임의 수정 불가**. 공식 예외는 운영진의 명시적 허용(예: 개인정보/권리 침해 삭제 등)에 한정. 제품 무료 접근 유지/보안·가동상태 확인은 허용 범위를 넘는 신규 기능·출품자료 변경으로 취급하지 않도록 보수적으로 운영.

- **휴무/비점검일은 0h 예정:** 문제를 발견하지 않았다면 임의로 매일 개발하거나 새 기능을 추가하지 않음. 외부 시스템 장애·Devpost 문의·계정 만료가 발생하면 위 2배 여유로도 부족할 수 있으므로 **추가 4~8h 단발 긴급 대응 예비를 별도 권고**(의무 투입 아님). 사용자의 다른 대회 일정과 중복 배정하지 않는다.
- **이 시간은 접수·접근이 확보된 이후만 유효한 조건부 추정치.** 본선용 30일 신규 개발 0h. 현재 PayPal 실제 Sandbox/AI/Production/공식 제출이 모두 미검증이므로, 11월 11일 전 [개발 작업표](DAILY_CAPACITY_PLAN_20261024.md)의 **82h 예상·164h 안전 확보**를 이 표로 대체하거나 조기 종료 처리하지 않는다.
- **작동/심사 접근이 안정적이면** 점검당 보통 0.5~1h만 소모한다. 심사위원 로그인, API 무료한도, 배포 만료와 PayPal Sandbox 장애가 있으면 문제가 시간으로 해결된다고 단정하지 않고 공식 문의·안전한 우회안·재산정을 기록한다.
- **제출 후 작품 개선 시** 별도 브랜치/포트폴리오에 준비할 수 있어도 심사 제출본을 임의 덮어쓰거나 이미 제출된 설명/영상 내용을 변경하지 않는다. 위 시간은 신기능 구현이 아니라 접근성과 제출 증거 유지용.

## 결과·수상 시 추가 작업 (별도 조건부)
- 실제 수상자 후보/확정 연락이 오면 출처 확인 → 요구 서류·기한 확인 → 개인정보/계좌·신분증은 **비공개 공식 채널**로만 제출. Public GitHub·채팅에 올리지 않음. 상금 지급/수상 사실은 공식 확인 전 주장 금지.
- 규정상 Required Forms는 발송 후 **10영업일 내 반환** 요구될 수 있다. 서류 확인·대응 기본 **2~4h**, 인증 오류와 국제 송금/세금 이슈 안전 여유 **4~8h** 추가를 잠정 가정(법률/세무 업무 필요 시 더 걸릴 수 있음). 상금·은행·신분자료는 사용자 직접 승인/조치.
- 수상하지 않더라도 공식 심사/출품 결과와 실제 코드/데모 증거로 일반 포트폴리오 정리 가능. **단순 참가/제출, Stage Two 심사, 수상**을 분리해 표시한다.
