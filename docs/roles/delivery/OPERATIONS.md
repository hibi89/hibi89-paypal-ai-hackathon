# 납품·국제 거래 단계 추적 — 담당 작업 규칙

- 대회: **PayPal AI Hackathon**. 역할 브랜치: `feature/delivery`. 이 브랜치 밖 코드·데이터/상위 `main`/총괄 브랜치는 승인 없이 변경 금지.
- 사용자 승인 전 기능은 잠정; 총괄 `lead/paypal`이 데이터 계약·우선순위·통합 최종 책임자.
- 목표/범위 후보: 계약/프로젝트 단계·납품 상태·지불 상태를 추적하는 기능 후보. PayPal 결제 상태와 중복/불일치 없이 통합 가능한지 검증.
- **첫 검증 지시:** 대회 심사와 기본 결제 MVP에 대한 추가 기여 확인, 결제 상태/납품 상태 구분 및 수정 가능한 최소 데이터 계약 제안.
- 제약: PayPal 상품 계정 권한과 결제 처리/에스크로에 대한 허위 약속 금지. 실제 에스크로 기능 존재 확인 전 구현·홍보 금지.
- 작업 시작: **자기 브랜치** `docs/roles/delivery/HANDOFF.md` → `docs/roles/delivery/STATUS.md` → 본 OPERATIONS → 루트 AGENTS/REQUIREMENTS → 원격 코드/SHA 확인.
- 구현 전 트리거·흐름·상태 저장/조회 분리·API 비용/Rate·idempotency/장애복구·보안 설계 A/B안을 총괄에게 보고. 승인 없는 외부 연동·결제·민감정보 노출·범위 변경 금지.
- 매 중요 작업 종료: 테스트/실API/CI·미검증 정확히 구분 → 자기 브랜치 `STATUS/HANDOFF` 갱신 → `TO_PAYPAL_LEAD.md`의 누적 메시지 갱신 → 원격 커밋 SHA 확인.
- 메시지는 GitHub를 통해 전달되며 다른 채팅으로 자동 전송되지 않는다.
