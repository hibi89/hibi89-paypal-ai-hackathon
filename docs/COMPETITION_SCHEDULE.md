## 3. PayPal 총괄이 반드시 지킬 마감·우선순위

- **현재 주요 과제:** PayPal Developer Sandbox 접근 검증, AI+PayPal 실제 핵심 사용, 공개 소스·LICENSE·3분 미만 영상·Devpost 제출.
- **다음 마감/준비:** 11/11 조기 완성작 제출 목표, 11/13 05:00 공식 마감. 초기 Sandbox 실패 시 대회 총괄/전체 총괄에게 즉시 보고..
- **마감 충돌:** KIC 예선 11/12 10:00 → PayPal 11/13 05:00은 **19시간 차이**. 이어 UGREEN 11/16 16:45가 온다. 사용자는 실제 참가자 1명이므로 세 플랫폼의 등록·최종 제출 조작을 같은 시기에 몰리지 않게 조정한다.
- **품질 판정:** '신청'≠'작품 생성'≠'최종 제출'≠'본선 진출'≠'수상'. CI 통과 ≠ 실제 API/브라우저 동작.
- **작업자 운영:** 총괄은 새 기능 지시 이전에 자기 대회의 세 기능 브랜치 메시지함·SHA를 확인한다. 기능 담당은 자신의 브랜치에서 작업하되 공식 마감 일정은 여기서 점검한다.
- **보고:** 공식 일정 변경, 제출 위험, 내부 목표 지연, 본선 발표/수상, 사용자 승인 사안 발생 시 자기 `lead/paypal`의 `docs/roles/lead/STATUS.md`·`HANDOFF.md`·`TO_HACKATHON_LEAD.md`를 갱신하고 통합 총괄이 재확인할 수 있게 한다.
- **보안:** Public GitHub에 로그인 정보, API 키, 팀/개인 식별 증빙, 미공개 제출물 원본을 업로드하지 않는다.
