## 4. '4시간 → 20시간' 반복 방지 — 실제 시간 관리 계약
- 매 `ㄱ` 또는 작업 시작에 **그날 날짜·해당 잔여 완료 기준·원격 HEAD·어제 이월·오늘 확보 가능한 시간**을 확인. 날짜만 흘렀다고 완료/다음 단계로 넘기지 않는다.
- 각 단위 시작 전 `예상 잔여시간(낙관 추정 금지)`와 `안전 확보시간`, 막힘 요소/외부 의존을 `LEAD_ACTIVE_WORK.md`의 다음 실제 작업에 기록. **소스 변경·테스트 증거가 없는 계획/문서만으로 완료 처리 금지.**
- 작업 도중 **실제 측정한 작업 시작/끝 KST·누적 경과시간**을 근거가 있을 때만 기록. AI 임의로 과거 실행 시간이나 사용자의 가용시간을 꾸며 쓰지 않는다.
- 예상보다 1.5배가 되거나, 안전 확보시간의 절반을 썼는데 테스트 가능한 진전이 없으면 **즉시 재산정하고 Stop & Pivot**. 동일 실패 방식 2회 무진전이면 새 접근 1~3개를 시간·비용·품질·제약으로 비교하여 결정. 임의 낙관적 '남은 4시간' 재설정 금지.
- 하루 **안전 확보시간이 부족하면 '오늘 완료 가능' 판정 금지**. 초과분은 `이월(일·시간)`·다음 날에 미치는 영향·조기 제출 위험을 기록하고, 승인 없는 품질/기능 축소 대신 사용자에게 판단을 보고.
- 날짜별 단위는 **작업 목표**이고 완료 강제 마감이 아니다. CI만 성공이면 합성 CI PASS로 기록, 실 Sandbox/브라우저/Production/Devpost 접수는 각각 실제 영수증·테스트 증거로 확인.
- 매일 상태 변경이 실제 생겼을 때만 `STATUS.md`/`HANDOFF.md`/`LEAD_ACTIVE_WORK.md`/상위 보고를 갱신해 GitHub SHA 검증. **자동 백그라운드 동기화 없음**.
