# PayPal — 매 작업 종료 일일 진행률·잔여시간 필수 보고

**2026-10-24 사용자 고정 지시.** 매 실제 작업을 마칠 때마다 그날 할당 작업 전체를 100%로 보아, 검증된 진행률 X%/100%와 남은 예상 작업시간 Y시간 및 지연 포함 남은 안전 확보시간 Z시간을 사용자 응답과 GitHub에 표시한다.

## 출처
- [검증 항목별 공식 원장](../data/paypal_daily_progress.json): day_id, 완료 기준/가중치, 증거, 진행률, 예상/안전 잔여시간, 실측, 차단, 이월.
- [날짜별 초기 작업 시간표](DAILY_CAPACITY_PLAN_20261024.md): 총 18일 예상 82시간/안전 164시간은 초기 배분 추정치이다.

## 엄격한 100% 진행률 기준
1. 매일 개발 시작 전 한정된 3~8개 검증 가능한 인수 기준을 정하고 각각 가중치 합계 100을 만든다. 실행 중 임의로 목표를 쪼개 수치를 부풀리지 않는다.
2. 진행률 = 상태가 VERIFIED인 기준의 weight_pct 합산이다. 코드만 작성하고 테스트 증거가 없거나 오류/CI 미확인이라면 VERIFIED 처리하지 않는다. 시간을 소비했다고 진행률을 올리지 않는다. 실패가 밝혀지면 진행률을 낮춘다.
3. 남은 예상시간은 미검증 작업에 필요한 경과시간을 작업 복잡도와 실제 장애에 따라 재산정한다. 처음에는 하루 총 예상시간 × (100 - 진행률)/100을 임시 계산 기준으로 사용할 수 있지만 난도가 균일하다는 보장은 없다. 반올림보다 정확한 막힘 원인이 중요하다.
4. 남은 안전 확보시간은 오류·검수·재시도까지 고려해 확보할 여유의 보수적 잔여 추정이다. **실측 경과시간과 분리**하여 기록한다. 실측 증거가 없으면 NOT_MEASURED. 이미 경과한 시간을 진행률/남은 시간 감소로 혼동하지 않는다.
5. 불확실하거나 원격 인증 등으로 막힌 잔여시간은 임의로 단정하지 않고 UNKNOWN/BLOCKED로 표시하고 이월 원인·대안·사용자 승인 필요사항을 남긴다. 하루 미완료를 억지로 100% 처리하지 않는다.
6. 100%는 **그날 허가된 작업 범위 100%**이며 결제 API, 실제 Sandbox, 전체 해커톤 출품 완성도가 아니다. 오프라인 통과와 Production 실증은 분리한다.

## 매 작업 완료 후 최종 보고서 필수 칸

|---|---|
| 일차·계획 날짜·오늘 범위 | PPL-D02 / 2026-10-26 / DB 영속·원자 점유 |
